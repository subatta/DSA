# Variant #5: Happy Number

**LeetCode #202 - Easy**

## Problem Statement
Write an algorithm to determine if a number n is happy.

A **happy number** is defined by the following process:
- Starting with any positive integer, replace the number by the sum of the squares of its digits.
- Repeat until the number equals 1 (happy), or loops endlessly in a cycle (not happy).

Return `true` if n is happy, `false` if it enters a cycle.

**Example:**
- Input: 19
- Process: 1² + 9² = 82 → 8² + 2² = 68 → 6² + 8² = 100 → 1² + 0² + 0² = 1 ✅

## 4-Step Analysis Framework

### Step 1: State Space Derivation

### **Problem Visualization:**
```
Happy number example: n = 19

19 → 1² + 9² = 1 + 81 = 82
82 → 8² + 2² = 64 + 4 = 68
68 → 6² + 8² = 36 + 64 = 100
100 → 1² + 0² + 0² = 1 ✓ (HAPPY!)

Unhappy number example: n = 2

2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 (cycle!)
    ↑_______________________________________|

Visualized as directed graph:
        2 → 4 → 16 → 37
            ↑                    ↓
            20 ← 42 ← 145 ← 89 ← 58

This is a CYCLE DETECTION problem in disguise!
```

### **Core Question:**
Does the sequence reach 1, or enter an infinite cycle?

### **Deriving from First Principles:**

**Observation 1:** Transformation creates a sequence
- Each number n → getNext(n) = sum of squares of digits
- This defines a function: f(n) = next number
- Starting from any n, we get sequence: n, f(n), f(f(n)), ...

**Observation 2:** Sequence must eventually repeat
- Why? The sum of squares is bounded!
- For a d-digit number, max value ≈ d × 81 (all 9's)
- For 3-digit number: 999 → 9²+9²+9² = 243 (smaller!)
- So numbers quickly decrease to small values
- Small set of values → must revisit some value → cycle forms

**Observation 3:** Only two outcomes
- **Happy:** Sequence reaches 1 (and stays: 1 → 1 → 1 ...)
- **Unhappy:** Sequence enters a cycle that doesn't include 1

**Observation 4:** This is cycle detection!
- HashSet approach: Store seen numbers, detect revisit
- Floyd's algorithm: Use fast & slow pointers
  - slow: one step (n → f(n))
  - fast: two steps (n → f(f(n)))
  - If happy: one pointer reaches 1
  - If unhappy: pointers meet in cycle

### **State Space Structure:**

**Type:** Cycle detection in number transformation sequence  
**Structure:** Sequence of numbers generated by sum-of-squares transformation  
**Cardinality:** Finite (bounded by largest possible sum for given digit count)

**State Space Example:**
```
Starting from 19:
19 → 82 → 68 → 100 → 1 (happy!)

Starting from 2:
2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 (cycle detected!)
```

**Key insight:** Every sequence either reaches 1 or enters a cycle (proven mathematically)

---

### Step 2: Brute Force with Value Tracing

**Approach:** Track seen numbers in HashSet, detect revisit

```csharp
public bool IsHappy_BruteForce(int n)
{
    var seen = new HashSet<int>();
    
    while (n != 1 && !seen.Contains(n))
    {
        seen.Add(n);
        n = GetNext(n);
    }
    
    return n == 1;
}

private int GetNext(int n)
{
    int sum = 0;
    while (n > 0)
    {
        int digit = n % 10;
        sum += digit * digit;
        n /= 10;
    }
    return sum;
}
```

**Value Trace for n=19 (happy):**

| Step | n | Calculation | seen | Result |
|------|---|-------------|------|--------|
| 0 | 19 | 1²+9²=82 | {} | Add 19 |
| 1 | 82 | 8²+2²=68 | {19} | Add 82 |
| 2 | 68 | 6²+8²=100 | {19,82} | Add 68 |
| 3 | 100 | 1²+0²+0²=1 | {19,82,68} | Add 100 |
| 4 | 1 | - | - | **Return true** ✅ |

**Value Trace for n=2 (unhappy):**

| Step | n | Calculation | seen | Result |
|------|---|-------------|------|--------|
| 0 | 2 | 2²=4 | {} | Add 2 |
| 1 | 4 | 4²=16 | {2} | Add 4 |
| 2 | 16 | 1²+6²=37 | {2,4} | Add 16 |
| 3 | 37 | 3²+7²=58 | {2,4,16} | Add 37 |
| 4 | 58 | 5²+8²=89 | {2,4,16,37} | Add 58 |
| 5 | 89 | 8²+9²=145 | ... | Add 89 |
| 6 | 145 | 1²+4²+5²=42 | ... | Add 145 |
| 7 | 42 | 4²+2²=20 | ... | Add 42 |
| 8 | 20 | 2²+0²=4 | ... | Add 20 |
| 9 | 4 | - | **Found in set!** | **Return false** ❌ |

**Complexity:**
- **Time:** O(log n) iterations (number of digits decreases)
- **Space:** O(log n) - Store visited numbers

### Step 3: Pruning Analysis - Can We Do Better?

**Key Observations:**

1. **This is cycle detection!** Similar to Linked List Cycle (Variant #1)
2. **Implicit sequence:** Each number points to next via GetNext() function
3. **Floyd's algorithm applies:** Fast & slow pointers work on any sequence!
4. **Mapping:** Think of GetNext() as following a "next pointer"

**Analogy:**
```
Linked List:     node.next
Number sequence: GetNext(n)

Both form chains that may cycle!
```

**Decision:** ✅ Apply Floyd's cycle detection with GetNext() as the "next" function!

### Step 4: Optimal Solution with Skeleton Transformation

```csharp
public bool IsHappy_Optimal(int n)
{
    int slow = n;
    int fast = n;
    
    do
    {
        slow = GetNext(slow);           // Move 1 step
        fast = GetNext(GetNext(fast));  // Move 2 steps
    }
    while (slow != fast);
    
    // If they meet at 1, it's happy
    return slow == 1;
}

private int GetNext(int n)
{
    int sum = 0;
    while (n > 0)
    {
        int digit = n % 10;
        sum += digit * digit;
        n /= 10;
    }
    return sum;
}
```

**Skeleton Transformation:**
```
BRUTE FORCE:
├── seen = HashSet()
├── while (n != 1 && !seen.Contains(n)):
│   ├── seen.Add(n)
│   └── n = GetNext(n)
└── return n == 1

         ↓

OPTIMAL:
├── slow = n, fast = n
├── do:
│   ├── slow = GetNext(slow)        [1 step]
│   └── fast = GetNext(GetNext(fast))  [2 steps]
├── while (slow != fast)
└── return slow == 1

KEY CHANGES:
- HashSet → Two pointers
- Explicit cycle check → Implicit via meeting
- O(log n) space → O(1) space
```

**Value Trace for n=19 (happy):**

| Iter | slow | fast | Action |
|------|------|------|--------|
| 0 | 19 | 19 | Initial |
| 1 | 82 | 68 | slow:19→82, fast:19→82→68 |
| 2 | 68 | 1 | slow:82→68, fast:68→100→1 |
| 3 | 100 | 1 | slow:68→100, fast:1→1→1 |
| 4 | 1 | 1 | slow:100→1, fast:1→1→1 |
| Meet at 1 | ✅ | **Return true** |

**Value Trace for n=2 (cycle):**

| Iter | slow | fast | Meet? |
|------|------|------|-------|
| ... | ... | ... | Eventually meet at some cycle value ≠ 1 |
| Final | 4 | 4 | **Return false** ❌ |

## Big-O Analysis

**Brute Force:**
- **Time:** O(log n) - Limited iterations before cycle
- **Space:** O(log n) - HashSet storage

**Optimal:**
- **Time:** O(log n) - Same iterations, constant factor difference
- **Space:** O(1) - Only two variables

**Key Advantage:** O(log n) → O(1) space with same time complexity!

---

## Pattern Recognition

**When to use:**
- ✅ Cycle detection in **any** sequence (not just linked lists!)
- ✅ Have a transformation function (GetNext)
- ✅ Sequence eventually cycles or terminates
- ✅ O(1) space preferred

**Key insight:** Floyd's algorithm works on **implicit** graphs where "next" is computed by a function!

---

## Why This Works

**Mathematical properties:**
1. Sum of squares of digits always produces finite values
2. For 3-digit numbers: max is 9²+9²+9² = 243
3. Sequence must eventually cycle (finite state space)
4. Happy numbers reach 1, unhappy numbers enter cycle excluding 1

---

## Edge Cases

1. **n=1:** Already happy, returns true immediately
2. **Single digit happy:** 1, 7 are happy
3. **Single digit unhappy:** 2-6, 8-9 enter cycles
4. **Large numbers:** Still converge quickly (digits decrease)
